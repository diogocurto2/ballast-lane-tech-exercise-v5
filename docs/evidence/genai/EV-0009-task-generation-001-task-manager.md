## Original AI-generated output

### Defect 1 - non-sequential task identifier

The first generated list used an inserted identifier to avoid renumbering:

```text
- [ ] T005 [P] Create `docker-compose.yml` ...
- [ ] T005a Verify compose configuration parses ...
- [ ] T006 [P] Create `.env.example` ...
```

This violates the sequential `T001, T002, T003...` identifier rule and made two tasks collide under a
`T\d{3}` scan. It also produced a false "duplicate T005" reading in validation.

### Defect 2 - 33 tasks with no file path

The first generated list contained 33 tasks whose descriptions named no path, for example:

```text
- [ ] T014 Run the Phase 2 tests and record the observed RED failures for each of T008 to T013 ...
- [ ] T023 Refactor Phase 2 code, rerun the suite, and record the result (depends on T022)
- [ ] T101 Run the complete suite from a clean checkout ...
```

The template requires "Include exact file paths in descriptions" and lists "missing file path" as a
wrong format. Run, refactor, and evidence tasks were the systematic gap because they do not
naturally name a source file.

### Defect 3 - implicit RED lineage on chained implementation tasks

The first list gave only the first implementation task in each group a direct RED dependency. Later
tasks chained to the previous implementation task:

```text
- [ ] T031 [US1] Implement ... (depends on T030)
```

The constitution requires every implementation task to depend on its corresponding observed RED
checkpoint, and treats "an implementation task whose dependency does not require an observed RED
checkpoint" as blocking. A chain through another implementation task leaves that lineage implicit.

## Review findings

- `[VERIFIED]` Defect 1: `T005a` violated sequential numbering and collided under a numeric scan.
  Corrected by folding the compose verification into `T007` and renumbering; the final list is
  `T001` to `T106` with no duplicates and no gaps.
- `[VERIFIED]` Defect 2: 33 tasks named no path. Corrected by naming a test project, a source
  directory, or the specific evidence record in every run, refactor, and evidence task. Final scan
  reports zero tasks without a path.
- `[VERIFIED]` Defect 3: implementation chains hid the RED lineage. Corrected so the first
  implementation task in each group depends directly on the RED checkpoint and each later task names
  the checkpoint it inherits, for example "depends on T030; RED via T029". Final count: 8 direct RED
  dependencies plus 24 inherited lineage statements, with no implementation task lacking one.
- `[AI-PROPOSED]` Task count and granularity: 106 tasks, of which 34 are Setup or Polish
  (non-story), 17 are Foundational, and the seven stories total 72. A coarser list would be faster
  to read but would blur which behavior each RED checkpoint covers.
- `[VERIFIED]` The two tasks that a follow-up scan flagged as "no path" (`T006`, `T103`) do carry
  exact root-level filenames (`.env.example`, `.gitignore`, `README.md`, `GENAI.md`); the initial
  scanner required a directory separator, so these were scanner false positives, not defects.

| Change | Reason | Technical justification |
| --- | --- | --- |
| Removed `T005a`; compose validation folded into `T007` | Sequential identifiers only | A stable, gap-free identifier sequence is what makes task references reviewable and machine-checkable |
