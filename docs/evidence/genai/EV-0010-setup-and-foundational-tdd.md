## Review findings

- `[VERIFIED]` `dotnet new sln` on SDK 10.0.404 emits `.slnx`; the artifact named by `plan.md` and
  `tasks.md` is `BallastLane.sln`. The AI regenerated the classic format with
  `dotnet new sln -n BallastLane --format sln` and removed the `.slnx` file.
- `[VERIFIED]` The AI's hand-written `.csproj` files dropped `TargetFramework`, and restore failed
  with `NETSDK1013`. `net10.0` was added to all 16 projects.
- `[VERIFIED]` One `Set-Content` failed with a file-in-use error while an MSBuild node still held the
  project file. `dotnet build-server shutdown` released it and the write succeeded on retry.
- `[VERIFIED]` All resolved backend packages sit on the .NET 10 line (10.0.15 for the Microsoft
  packages, Npgsql 10.0.3) or the 8.19.2 IdentityModel line that
  `Microsoft.AspNetCore.Authentication.JwtBearer` 10.0.15 itself requires.
- `[VERIFIED]` A transitive package scan found no `EntityFramework`, `Dapper`, `MediatR`, or
  `Mediator` reference.

## Corrections and improvements

| Change | Reason | Technical justification |
| --- | --- | --- |
| Regenerated the solution as `BallastLane.sln` with `--format sln` | SDK 10 defaults to `.slnx` | The named deliverable in the plan, tasks, and quickstart is `.sln`, and every command in those artifacts references it |
| Added `<TargetFramework>net10.0</TargetFramework>` to all 16 projects | Restore failed with `NETSDK1013` | A modern SDK-style project requires a target framework; the plan fixes `net10.0` |
| Removed template placeholders (`Class1`, `WeatherForecast`, `UnitTest1`, `.http` files) | Generated scaffolding that no task requires | Dead code is prohibited by `coding-standards.md` 4 |
| Rewrote `vite.config.ts` to import `defineConfig` from `vitest/config` | The `test` block is not part of Vite's `defineConfig` type | Frontend strict type checking must pass with no `any` or suppressed error |
| Changed the API unit cancellation test to assert an observable failure | The original test asserted `OperationCanceledException` from an unopened connection, which Npgsql cannot produce | The driver rejects a closed connection first, so the original premise was untestable; token forwarding is now verified against a real open connection in `tests/integration/BallastLane.PostgreSql.Tests/ConnectionCancellationTests.cs` |
| Architecture test reads `.csproj` declarations instead of runtime assembly references | The compiler omits an unused assembly reference, so a declared violation could pass unnoticed | A declared `Dapper` reference failed the assembly-based check only after code used it; the project-file check catches the declaration itself |
| Disabled test parallelization in the two migration test assemblies | Parallel `CREATE DATABASE` statements contended on the template lock and produced 15 s and 30 s timeouts | Observed failures disappeared once tests ran sequentially; each test still owns an isolated scratch database |
| Added `.env` locally for verification runs | Compose requires the variables the example declares | `.env` is git-ignored as `.gitignore` already provides; only placeholders reach the repository |
